# Clone.AI

Clone.AI is a premium, multimodal AI chat application built with Next.js. It provides a focused conversational interface powered by Google Gemini, with chat history, language preferences, optional web search, file attachments, light and dark themes, and Supabase-backed persistence.

The application is currently configured to operate as a guest-friendly experience. The login screen includes Google OAuth wiring, but the main chat page temporarily uses a guest user while authentication is being finalized.

## Features

- Chat with Google Gemini 2.5 Flash through a server-side API route.
- Maintain conversation context using the most recent 15 previous messages.
- Send text prompts and supported file or image attachments.
- Enable Google Search retrieval for prompts that need current information.
- Use English, Hindi, or Hinglish response preferences.
- Create, select, and delete conversations from the sidebar.
- Delete all locally stored conversation history.
- Persist chats and messages in Supabase when available.
- Fall back to browser `localStorage` when Supabase is unavailable.
- Switch between light and dark themes; the preference is saved locally.
- Render assistant responses with Markdown, including formatted code blocks.

## Technology Stack

- **Framework:** Next.js 16.2.1 with the App Router

## Installation

1. Clone the repository and enter the project directory:

    ```bash
    git clone <repository-url>
    cd Clone.AI
    ```

2. Install dependencies:

    ```bash
    npm install
    ```

3. Create a file named `.env.local` in the project root and add the required environment variables:

    ```env
    NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
    NEXT_PUBLIC_SUPABASE_ANON_KEY=your-supabase-anon-key
    GEMINI_API_KEY=your-gemini-api-key
    ```

    Never commit `.env.local` or expose `GEMINI_API_KEY` in client-side code. The `NEXT_PUBLIC_` variables are intended to be available in the browser; the Gemini key is used by the server API route.

## Supabase Setup

The application reads and writes two tables: `chats` and `messages`. Create them in the Supabase SQL Editor with a schema similar to the following:

```sql
create table public.chats (
   id uuid primary key default gen_random_uuid(),
   title text not null,
   user_id uuid,
   created_at timestamptz not null default now()
);

create table public.messages (
   id bigint generated by default as identity primary key,
   chat_id uuid not null references public.chats(id) on delete cascade,
   role text not null check (role in ('user', 'assistant')),
   content text not null,
   attachments jsonb,
   created_at timestamptz not null default now()
);
```

For a production deployment, enable Row Level Security and add policies that restrict each user to their own chats and messages. The current client code also attempts public or guest access, so the exact policies must match the authentication model you intend to use. Do not leave broad write access enabled for a public production database.

### Optional Google OAuth

To enable the Google sign-in flow:

1. Configure Google as a provider in Supabase Authentication.
2. Add the Supabase callback URL to the Google OAuth client configuration.
3. Add the local and production application URLs to Supabase's allowed redirect URLs.
4. Replace the temporary guest behavior in `src/app/page.tsx` with an authenticated session check before relying on `user_id` and user-specific RLS policies.

## Using Clone.AI

1. Open the application and start a new chat.
2. Type a prompt in the message box and submit it.
3. Use the quick-reply language controls to choose English, Hindi, or Hinglish responses.
4. Use the attachment control to include supported files or images with a prompt.
5. Enable the globe/search control when the response should use Google Search retrieval.
6. Select an existing conversation in the sidebar to load its messages.
7. Open Settings to change the theme or clear conversation history.

The assistant can make mistakes. Verify important medical, legal, financial, or otherwise time-sensitive information independently.

## How Data Flows

1. The browser collects the current message, language preference, attachments, and search setting.
2. A new chat is inserted into Supabase when possible. If that fails, a generated local ID is used.
3. User messages are saved to both `localStorage` and Supabase when possible.
4. The browser sends the conversation to `POST /api/chat`.
5. The API route builds a prompt, includes up to 15 previous messages, adds attachment data, and calls Gemini 2.5 Flash.
6. The assistant response is returned to the browser and saved with the conversation.

Local storage keys currently include:

- `clone_ai_theme` for the selected theme.
- `clone_ai_history` for locally cached conversation summaries.
- `clone_ai_messages_<chat-id>` for locally cached messages.

## API Reference

### `POST /api/chat`

Request body:

```json
{
   "messages": [
      { "role": "user", "content": "Explain recursion" }
   ],
   "language": "en",
   "attachments": [],
   "isSearchEnabled": false
}
```

Supported language values are `en`, `hi`, and `hng`. Attachments use objects containing `data` as a data URL, `mimeType`, and `name`.

Successful response:

```json
{
   "role": "assistant",
   "content": "..."
}
```

Configuration or generation failures return a JSON error response with HTTP status `500`.

## Troubleshooting

### Gemini requests fail

- Confirm `GEMINI_API_KEY` exists in `.env.local`.
- Restart the development server after changing environment variables.
- Check the server terminal for `Gemini Route Error` output.
- Confirm the API key has access to Gemini 2.5 Flash and that quota is available.

### Supabase history is empty

- Confirm both `NEXT_PUBLIC_SUPABASE_*` variables are correct.
- Verify that the `chats` and `messages` tables exist and match the expected columns.
- Check Supabase policies and browser console errors.
- The app should continue using local storage when remote persistence is unavailable.

### Google login does not redirect correctly

- Verify Google OAuth is enabled in Supabase.
- Check the provider callback and redirect URL configuration.
- Confirm the application origin is included in Supabase's allowed redirect URLs.

## Security Notes

- Keep `GEMINI_API_KEY` server-only and out of source control.
- Add authentication and Row Level Security before treating stored conversations as private.
- Review attachment size and MIME-type limits before exposing the app publicly.
- Add request validation and rate limiting to `POST /api/chat` for production use.
- Treat model output as untrusted text and verify important claims.
